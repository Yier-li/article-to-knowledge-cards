# 知识卡片生成

## Overview

把一篇文章（粘贴的正文或本地 Markdown/TXT 文件）提炼成 5~8 张可复习的知识卡片。
核心价值不在"总结"，而在"筛选与转化"：判断哪些是真正值得记住的知识，把每个知识点
写成一张能独立理解、能自我检验的卡片。

## 能力边界

| 请求 | 处理 |
|------|------|
| 粘贴的正文 | 支持 |
| 本地 `.md` / `.txt` / `.markdown` 文件 | 支持（读取后处理） |
| 网页链接 / 网页抓取 | 不支持。请用户把正文粘贴进来，或另存为 `.md`/`.txt` |
| PDF / Word / 图片 / 扫描件 | 不支持。请用户先导出为纯文本 `.txt` 或 `.md` |
| Anki 导入（`.apkg`、制表符分隔） | 不支持。只输出 Markdown，由用户自行整理 |
| 图形界面 / 可视化卡片排版 | 不支持。只输出 Markdown 文本 |

遇到不支持的格式，**不要尝试变通处理，也不要假装成功**。一句话说明不支持，
并给出用户能立刻执行的替代方案（如"把这个 PDF 导出成 txt 后再给我"）。

## 工作流

### Step 1：取到原文

- 用户给了文件路径 → 读取文件。读不到、编码异常或扩展名不在支持列表内，直接说明并停止。
- 用户粘贴了正文 → 直接用。
- 两者都没给 → 询问一次，不要猜。
- 一次给了多个文件 → 默认每个文件单独产出一套；用户明确要求合并时产出一套，
  并在「说明」里注明来源。
- 估算字数。超过 8000 字分段读完再统一盘点，不要只读开头就动手。

### Step 2：盘点候选知识点

通读全文，列出所有候选知识点。每个候选记录一句话概括、出处锚点（原文哪一段）、
以及原文是否**明确陈述**。**出处锚点只用于自检溯源，不写进最终输出。**

直接划掉、不进入候选的内容：
- 作者的个人感慨、抒情、铺垫、过渡句
- 重复的强调（同一论点换个说法再说一遍）
- 纯背景介绍中与结论无关的部分
- 举例中的细枝末节
- 营销话术、号召性语句、作者自我介绍

三类容易误判的内容，按下述规则处理：
- **操作清单 / 建议列表**：逐条判断。某条建议是前文某知识点的落地动作 → 并入该卡片的
  "简明解释"末尾（写成"所以做法是……"），**不占"例子"字段**；某条是独立可执行方法
  且前文没有对应知识点 → 单独成卡。**判断单位是一条独立的方法，不是"一条理由 +
  一条做法"，后者属于同一张卡。**
  **不要因为"几条放一起会一卡多点"就整块丢弃**，那通常是文章最实用的部分。
- **引用的研究、数据、案例**：支撑某个论断的，放进该卡片的"例子"；只有文章主论点
  本身就是该研究结论时，才单独成卡。
- **数字与事实**：单独看只是事实罗列的，不立卡；它若用来支撑某结论，作为该卡片的例子。

### Step 3：筛选

对候选逐条过这 5 道关，任一关不过就淘汰：

1. **溯源**：原文能找到明确依据吗？找不到 → 淘汰。
2. **独立性**：能脱离上下文单独理解吗？需要大段原文背景才成立 → 降级或淘汰。
3. **知识性**：是"一个可迁移的结论 / 机制 / 方法 / 判断标准"吗？
4. **一卡一点**：一句话里出现"并且 / 同时 / 另外"连接的两个独立论断 → 拆成两张。
5. **去重**：与另一候选重复 → 合并为一张，保留信息量更大的表述。

#### 去重与拆分的裁决（两条规则冲突时按此顺序判）

先判"是不是同一个断言"，再判"要不要拆"：

- **去重看断言同一性，不看字面重叠**。把两张卡片的"核心知识"句互相替换，若读者得到
  的事实与行动指引没变 → 判为重复，合并。
  以下**不算重复**，分开成卡：机制与其后果（"回表是随机 I/O"与"命中行多时优化器放弃
  索引"）；一条规则与其边界条件（"最左前缀"与"范围查询终止后续列"）。
- **拆分只在"并列了两个可独立成立的断言"时触发**（两个断言能各自单独考、单独忘）。
  对比句是**一个相对判断的两半，不拆**，例如"成熟团队远程净收益为正、新团队代价被低估"。
- **分类框架不立卡**：文章先给出"分三类看"的框架、随后逐类展开时，若各类结论已各自
  成卡，框架本身只是目录，不是知识点，不立卡。

### Step 4：定量与淘汰

- 目标 **5~8 张**。
- 通过筛选的不足 5 张 → **输出实际数量**，并在「说明」里写明原因。
  **绝不允许为凑数把一句结论拆成多张，或补充原文没有的内容。**
- 通过筛选的超过 8 张 → 按以下顺序淘汰到 8 张：
  1. 类别：主论点 > 分论点 > 机制/方法 > 边界条件与反例 > 具体事实与数据；
  2. 同类别内：覆盖原文篇幅大的优先，位于标题、开头或结尾的优先；
  3. **同一小节内最多取 3 张**，避免卡片集中在文章的某一段（无小标题时按自然段算）；
  4. 被舍弃的方向在「说明」里列出来。
- 原文极短、全是抒情或纯营销、几乎无可提取知识 → 输出 1~2 张并说明；
  确实没有知识点时，直接告诉用户，不要用空话填充。

### Step 5：写卡片

每张卡片 = 一个标题 + 三个字段：

```markdown
### 卡片 N｜一句话标题

- **核心知识**：一句话，≤ 40 字（硬约束）。陈述文章的结论、机制或方法，可独立理解。
- **简明解释**：2~4 句，讲清"为什么成立 / 怎么来的 / 适用条件"。只重组原文信息。
- **例子或自测问题**：二选一 —— 原文有例子优先用原文例子；没有则出一道自测题。
```

写作约束：
- **标题**：一句话知识点，不是名词短语。写"缓存失效由 TTL 决定"，不写"关于缓存"。
- **核心知识**：陈述句，不写"作者认为……"这类转述腔。超过 40 字就压缩。
- **例子**：指原文中出现的具体实例、数据、场景、对比或引文。**操作建议和方法步骤
  不算例子**，它们属于"简明解释"或需单独成卡。
- **自测问题**：必须附一行答案（缩进写 `  - 答案：…`），答案在原文里能找到。
  不要出原文答不了的开放题。用户明确要求"只出题不给答案"时才省略答案行。
- **禁止编造**：不添加原文没有的数据、数字、人名、书名、研究结论、引文、出处。
- **常识补充**：只对"读懂该知识点所必需的定义性常识"开放，一卡最多一处，
  必须写成「（常识补充，非原文内容）」。用它绕过禁编造规则属于严重违规。
- **代码与术语**：原文的代码、命令、SQL 原样保留，不缩写不改写；术语除非原文已解释，
  否则不自行为其下定义。
- **篇幅**：整卡 80~180 字（含标点，粗估即可，不必精确）。解释写满 4 句仍讲不清 →
  该知识点太重，拆开或淘汰。引用的原文数据较长时，先把解释压到 2 句；
  仍超上限时**以保住原文数据为准**，字数让步。

#### 观点型文章的特殊处理

若原文整体是评论或观点文（主观判断多于实证），**不要逐张标注"作者主张："**——
那会让每张卡都戴着同一顶帽子。改为在头部加一行整体声明：

```markdown
> 体裁：评论文章，以下结论多为作者主张，非实证定论
```

只有"以事实为主、少数几句为主观点"的非评论体文章才逐张标注，格式是在"核心知识"
开头加 `作者主张：`。判断不准时，宁可整体声明。

### Step 6：自检

输出前逐项确认，任何一项不过就改：

- [ ] 每张卡片的"核心知识"都能在原文找到出处
- [ ] 没有两张卡片讲同一件事（按 Step 3 的断言同一性判断）
- [ ] 没有一张卡片塞了两个可独立成立的知识点
- [ ] 没有任何一张卡片包含原文之外的事实；常识补充已标注且每卡不超过一处
- [ ] 每张卡片脱离全文也能读懂
- [ ] "核心知识" ≤ 40 字，整卡 80~180 字
- [ ] 自测题都附了答案，且答案能在原文找到
- [ ] 观点型文章已做整体声明或逐张标注
- [ ] 数量与 Step 4 的结论一致
- [ ] 语言与原文一致（中文文章出中文卡片）

### Step 7：输出

- 输出路径优先级：**用户指定 > 输入为文件时的源文件同目录 > 粘贴文本时的当前工作目录**。
  - 输入是文件且未指定路径 → `<源文件名>-知识卡片.md`
  - 输入是粘贴文本且未指定路径 → `知识卡片.md`；已存在则加 `-2`、`-3`
- 覆盖已存在的文件前先确认；用户在本次请求中已明确授权覆盖时不再确认。
- 文件用 UTF-8 编码。标题取原文一级标题；没有则用文件名（去扩展名）；超过 30 字截断。
- 卡片**按原文出现顺序**排列，便于回溯。
- 在回复里**同时展示完整卡片内容**，不要只说"已生成文件"。

文件结构：

````markdown
# 知识卡片：<来源标题>

> 来源：<文件路径 或 "用户粘贴正文">｜卡片数：N
> 体裁：评论文章，以下结论多为作者主张，非实证定论（仅观点型文章加此行）

### 卡片 1｜...

### 卡片 2｜...

## 说明

- **卡片数量**：N 张，<是否符合 5~8 张的目标，不符合请说明原因>
- **被合并或舍弃的内容**：...
- **原文局限**：...
````

## 常见错误处理

| 情况 | 处理 |
|------|------|
| 原文是新闻快讯，只有事件没有知识 | 如实输出 1~3 张（如"交易金额未披露"这类不构成知识点，不要成卡） |
| 原文是纯观点输出，无论证 | 输出观点 + 作者给出的理由，按 Step 5 做整体声明 |
| 原文含大量未解释的专业术语 | 只提取能读懂的部分；不要自行定义术语 |
| 用户要求"必须做满 8 张" | 说明凑数会牺牲质量，给出实际能做的数量 |
| 用户要求转成 Anki / PDF / 网页 | 明确说明不支持，给替代方案 |
